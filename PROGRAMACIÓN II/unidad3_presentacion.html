3.1 · Programación orientada a eventos

El programa espera, no actúa.

En la programación orientada a eventos (POE) el flujo no avanza línea por línea: avanza cuando ocurre algo. Un clic, una tecla, un temporizador, un mensaje del sistema.

Componentes esenciales

  • Evento: hecho observable durante la ejecución (un clic, una tecla).
  • Fuente de evento: objeto que lo produce (botón, ventana, sensor).
  • Manejador o callback: función que se ejecuta como respuesta.
  • Bucle de eventos: ciclo continuo que detecta y despacha.
  • Cola de eventos: estructura donde se almacenan los eventos pendientes.
Modelo secuencialOrientado a eventos
Flujo lo decide el código.Flujo lo deciden las acciones del usuario.
Termina al ejecutar la última línea.Vive hasta que se cierre la ventana.
Útil para cálculo y lotes.Útil para interfaces interactivas.
3.1 · Ejemplo en Tkinter

Un botón, una función.

La biblioteca estándar tkinter de Python implementa el paradigma orientado a eventos. Observa que la función saludar no se invoca con paréntesis al asignarla a command: se está pasando la referencia a la función, no su resultado.

# archivo: evento_basico.py
import tkinter as tk

def saludar():
    print("¡Hola! Se ha presionado el botón.")

ventana = tk.Tk()
ventana.title("Primer evento")
ventana.geometry("300x150")

boton = tk.Button(ventana, text="Salúdame", command=saludar)
boton.pack(pady=40)

ventana.mainloop()
mainloop() Esta llamada inicia el bucle de eventos. A partir de ese momento Python deja de ejecutar línea por línea y se queda escuchando: cuando ocurre un evento, ejecuta su manejador y vuelve a escuchar.

3.1 · El método bind()

Más allá del clic.

El parámetro command solo cubre el clic principal. Para reaccionar a otros eventos —teclas, doble clic, movimiento del ratón, foco— Tkinter ofrece el método bind(), que vincula un evento concreto con una función manejadora.

def al_presionar_tecla(evento):
    print(f"Tecla: {evento.keysym}")

ventana.bind("<Key>", al_presionar_tecla)
ventana.bind("<Double-Button-1>", al_hacer_doble_clic)

Eventos de ratón

<Button-1> clic izquierdo
<Button-3> clic derecho
<Double-Button-1> doble clic
<Motion> movimiento del puntero

Eventos de teclado y foco

<Key> cualquier tecla
<Return> tecla Enter
<FocusIn> el widget gana foco
<FocusOut> el widget pierde foco

3.2 · Experiencia de Usuario

No es lo que se ve: es lo que se vive.

La Experiencia de Usuario (UX) es el conjunto de percepciones, emociones y respuestas que una persona experimenta al usar un producto. La UI es el aspecto visual; la UX es todo lo demás.

Los siete pilares de la UX

Utilidad

Resuelve una necesidad real.

Usabilidad

Fácil de aprender y eficiente.

Accesibilidad

Personas con distintas capacidades pueden usarlo.

Deseabilidad

Genera respuesta emocional positiva.

Encontrabilidad

Las funciones son fáciles de localizar.

Credibilidad

El usuario confía en el sistema.

3.2.1 · Proceso de diseño UX

Un ciclo, no una línea.

El diseño UX es un proceso iterativo centrado en el usuario. Distintos modelos (Design Thinking, Doble Diamante, ISO 9241-210) coinciden en seis etapas esenciales que se repiten en ciclos.

EtapaQué se hace
1. InvestigaciónComprender a los usuarios mediante entrevistas, observación, encuestas.
2. DefiniciónSintetizar hallazgos en personas, mapas de empatía, escenarios.
3. IdeaciónGenerar muchas posibles soluciones (brainstorming, sketching).
4. PrototipadoConvertir ideas en wireframes y maquetas tangibles.
5. EvaluaciónProbar con usuarios reales y detectar problemas.
6. ImplementaciónConstruir el producto y reiniciar el ciclo con lo aprendido.
Iteración constante Las etapas no son lineales. Durante la evaluación pueden descubrirse nuevos requisitos que obliguen a regresar a la investigación. La iteración es esencial.

3.2.2 · Análisis UX

Las 10 heurísticas de Nielsen.

El análisis UX es el puente entre escuchar a los usuarios y diseñar soluciones. Una de sus herramientas más usadas es la evaluación heurística basada en los 10 principios de Jakob Nielsen.

Heurísticas 1-5

1. Visibilidad del estado del sistema
2. Coincidencia con el mundo real
3. Control y libertad del usuario
4. Consistencia y estándares
5. Prevención de errores

Heurísticas 6-10

6. Reconocer antes que recordar
7. Flexibilidad y eficiencia
8. Diseño estético y minimalista
9. Recuperación de errores
10. Ayuda y documentación

Otras técnicas frecuentes

  • Personas: perfiles ficticios pero realistas de los usuarios.
  • Mapas de empatía: qué piensa, siente, dice y hace el usuario.
  • Customer Journey Map: etapas, emociones y puntos de contacto.
  • Pruebas de usabilidad: observar a usuarios reales completando tareas.

3.3 · Interfaz gráfica de usuario

De la línea de comandos a la ventana.

Una GUI (Graphical User Interface) es el conjunto de elementos visuales que permite interactuar con un programa mediante ventanas, botones e iconos, en contraposición a la CLI, donde la interacción se hace con texto.

Componentes habituales

  • Ventanas: contenedores principales de la aplicación.
  • Widgets: etiquetas, botones, cajas de texto, listas, menús.
  • Contenedores: frames que agrupan visualmente otros widgets.
  • Gestores de geometría: organizan los widgets en la ventana.
  • Diálogos: ventanas auxiliares para entrada o confirmación.
Bibliotecas Python para GUI Tkinter (estándar, multiplataforma), PyQt (potente y profesional), Kivy (orientada a táctil y multitoque) y wxPython (apariencia nativa). En este curso usamos Tkinter por venir incluida en Python.

Los tres gestores de geometría

pack()

Apila los widgets en una dirección (arriba, abajo, izquierda, derecha). Sencillo, para diseños lineales.

grid()

Cuadrícula de filas y columnas. Ideal para formularios y diseños tabulares.

place() Posicionamiento por coordenadas absolutas. Útil en casos puntuales. Nunca mezcles pack() y grid() en el mismo contenedor: provoca conflictos. Si necesitas combinar disposiciones, usa Frames distintos.
3.3.1 · Formulario con grid

Un formulario funcional.

import tkinter as tk
from tkinter import messagebox

def registrar():
    nombre = entrada_nombre.get()
    edad = entrada_edad.get()
    if nombre == "" or edad == "":
        messagebox.showwarning("Campos vacíos",
                               "Por favor completa todos los campos.")
        return
    messagebox.showinfo("Registro exitoso",
                        f"Bienvenido(a) {nombre}, tienes {edad} años.")

ventana = tk.Tk()
ventana.title("Registro")

tk.Label(ventana, text="Nombre:").grid(row=0, column=0, padx=10, pady=10)
entrada_nombre = tk.Entry(ventana)
entrada_nombre.grid(row=0, column=1)

tk.Button(ventana, text="Registrar", command=registrar)\
    .grid(row=2, column=0, columnspan=2, pady=20)

ventana.mainloop()

3.4 · Manejo de excepciones

Cuando algo sale mal.

Un programa robusto no es el que nunca falla, sino el que sabe qué hacer cuando algo falla. Python distingue tres tipos de errores:

Errores de sintaxis

El código no cumple las reglas del lenguaje. El intérprete los detecta antes de ejecutar.

Errores lógicos

El programa se ejecuta sin fallos pero produce resultados incorrectos. Solo se detectan con pruebas.

Excepciones (errores en tiempo de ejecución)

El código es válido pero algo falla durante la ejecución: división entre cero, archivo inexistente, conversión inválida. Son el foco de este tema.

Excepciones comunes

ExcepciónCuándo se produce
ZeroDivisionErrorDivisión entre cero.
ValueErrorConversión inválida (p. ej. int("hola")).
TypeErrorOperación entre tipos incompatibles.
IndexErrorÍndice fuera del rango de una lista.
FileNotFoundErrorArchivo que no existe.
3.4 · try / except / else / finally

Atrapa, responde, continúa.

try:
    # Bloque donde puede ocurrir una excepción
    numero = int(input("Introduce un número: "))
    resultado = 10 / numero
except ZeroDivisionError:
    print("No se puede dividir entre cero.")
except ValueError:
    print("El dato no es un número válido.")
except Exception as e:
    print(f"Error inesperado: {e}")
else:
    # Solo si NO hubo excepción
    print(f"Resultado: {resultado}")
finally:
    # Se ejecuta SIEMPRE
    print("Fin del intento.")

Buenas prácticas

  • Captura excepciones específicas antes que genéricas.
  • Evita except: sin tipo: oculta errores reales.
  • En el try solo el código que realmente puede fallar.
  • Usa finally para liberar recursos (cerrar archivos, conexiones).

3.4 · Pruebas unitarias

Verificar antes de entregar.

Las pruebas verifican que el programa cumpla los requisitos. Existen varios niveles: unitarias (unidades pequeñas), integración (varios módulos), sistema (programa completo) y aceptación (las realiza el cliente).

unittest: pruebas con la biblioteca estándar

# archivo: test_operaciones.py
import unittest
from operaciones import sumar, dividir

class PruebasOperaciones(unittest.TestCase):

    def test_sumar_enteros(self):
        self.assertEqual(sumar(2, 3), 5)

    def test_dividir_entre_cero(self):
        with self.assertRaises(ZeroDivisionError):
            dividir(10, 0)

if __name__ == "__main__":
    unittest.main()
Métodos assert más usados assertEqual(a, b) verifica igualdad · assertTrue/False(x) evalúa condiciones · assertAlmostEqual compara reales con tolerancia · assertRaises verifica excepciones · assertIn comprueba pertenencia.
